# テスト

## 対象

次のいずれかを確認するテストだけを実装する。

- 壊れた場合の影響や重要度が高い振る舞い
- 通常利用では発覚しにくい問題
- Plugin、SDK、外部APIなどの外部依存との契約

各テストについて、保証する振る舞い、検出する現実的な不具合、既存のテストでは検出できない理由を説明できるようにする。説明できないテストは実装しない。

## 実装方法

外部から観測できる値、状態、操作または失敗を確認する。関数名、定数、内部の分岐などを実装と同じ形で言い直すテストは作らない。

中心の処理は外部サービスなしで確認する。接続部では外部の値と失敗が契約へ正しく変換されることを確認する。実際の通信や保存を使う確認は、外部契約を証明するために必要な範囲へ限定する。

一つのテストでは一つの契約または失敗条件を扱う。同じ判断を受ける入力の違いは、一つのテストまたは表形式へまとめる。

対象となる非自明な処理には、壊れたときに失敗する最小の実行可能な確認を一つ残す。既存のテスト方法または単純な自己確認で証明できる場合は、新しいテスト基盤や共通準備を追加しない。
